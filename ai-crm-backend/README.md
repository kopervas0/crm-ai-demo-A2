# AI CRM — бэкенд (прототип)

Слой данных и AI-аналитики под «вторую фазу» проекта из вакансии: телефония,
Telegram/WhatsApp, AI-транскрибация звонков, речевая аналитика и авто-задачи на
базе LLM.

Написан на чистой стандартной библиотеке Python (`sqlite3`, `re`, `unittest`) —
**без единой внешней зависимости**, поэтому запускается где угодно без `pip install`.

## Структура

```
ai-crm-backend/
├── src/
│   ├── db.py     — модель данных (SQLite): leads, calls, tasks + дедупликация лидов
│   └── ai.py     — речевая аналитика (intent/sentiment/summary) + правило авто-follow-up
├── scripts/
│   └── demo.py   — сквозная демонстрация: звонок → транскрипт → AI-анализ → авто-задача
├── tests/
│   └── test_db.py — 11 тестов на слой данных и AI-аналитику
└── data/         — сюда кладётся SQLite-файл при работе
```

## Как запустить

Из папки `ai-crm-backend`:

```bash
python scripts/demo.py
```

Демонстрирует полную цепочку на нескольких примерах звонков и печатает, какие
задачи AI поставил менеджеру автоматически.

Тесты:

```bash
python -m unittest discover -s tests -v
```

## Где подключается настоящий LLM

Вся речевая аналитика идёт через `analyze_transcript()` в `src/ai.py`, а та —
через единственную функцию `_call_llm()`. Сейчас это заглушка: если нет ключа,
код прозрачно откатывается на детерминированный rule-based анализ (для офлайн-демо
и тестов). Чтобы включить реальную модель — задать переменную окружения
`OPENROUTER_API_KEY` (или `CLAUDE_API_KEY`) и раскомментировать заготовку запроса
к OpenRouter внутри `_call_llm()`. Остальной код менять не нужно — ответ модели
всё равно проходит через `_validate_llm_output()`, который приводит `intent` и
`sentiment` к допустимым значениям.

## Как связано с фронтендом

`intent`, `sentiment`, `source`, статусы лидов и задач заданы теми же наборами
значений, что использует фронтенд-раздел воронки. Следующий шаг — REST API поверх
`db.py`, чтобы фронтенд брал данные из этой базы вместо `localStorage`.
